# spec 目录分类与演进规则

`.trellis/spec/` 下的规范分两类，演进规则不同。各层 index.md 头部有对应的分类声明。

## 通用规范（冻结层）

- **范围**：`wg-skills/` —— 外部仓库 [jiushiwon/wg-skills](https://github.com/jiushiwon/wg-skills)
  吸收的通用全栈工程规范（Apache-2.0，来源与修改声明见该层 `NOTICE.md`）
- **性质**：参考资料，**不是本项目的强制约定**；用于与本仓库技术栈无关的新项目场景
  （后端服务、独立站点、小程序、桌面端等）
- **演进规则**：**冻结不可修改**。吸收任务（`11-01-absorb-wg-skills`）归档之时即冻结——
  此后发现过时、错误或缺口，**不在此层修原文**：勘误记录到项目规范侧，或在引用处标注。
  未来吸收新的外部材料 → 走独立吸收任务，在本层**新增**文件（新增不算修改既有文件），
  并同步补 `NOTICE.md` 来源声明。

## 项目规范（学习收敛层）

- **范围**：
  - `frontend/` —— 本仓库 monorepo（portal-web / iam-web / packages）的强制开发约定
  - `guides/` —— 项目沉淀的思维方法论（跨层思考、代码复用等）
- **性质**：本项目的强制约定与工作方法论，AI 子代理写/评审本仓库代码前必读对应指南
- **演进规则**：**不停学习收敛**——任务 check 阶段把新经验、踩坑、实测结论沉淀回本层；
  过时规则随实践修订；每次沉淀经 git 历史可追溯。

## 优先级

**项目规范 > 通用规范**。写本仓库代码一律以 `frontend/` 为准；通用层仅在上述
「新项目」场景使用。两层冲突时，以项目规范为准（`wg-skills/index.md` 边界声明同此）。
