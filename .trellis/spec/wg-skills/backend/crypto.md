# 按场景加密选型规范

> 合并转写自 wg-skills 的 1 个技能：`crypto-scenario-skill`（场景决策表 + 密码存储 /
> 支付验签 / JWT 选型 / AI 约束块 / 上线自查清单等 references）。
> 规则实质保留原文，触发词/frontmatter/与规则无关的叙述已剥离。
> 按场景而不是按算法名给结论：每个场景回答**推荐什么、为什么、绝对不能用什么**。

## 一、场景决策表

| 场景 | 推荐 | 一句话理由 | 绝对禁止 |
|------|------|------------|---------|
| 用户密码存储 | bcrypt（cost 12）或 Argon2id | 故意算得慢，让爆破成本极高 | MD5 / SHA1 / SHA256 裸哈希、可逆加密、自研 |
| 微信支付回调验签 | RSA-SHA256（平台证书验签）+ 敏感字段 AEAD_AES_256_GCM | 官方强制算法，私钥不出商户 | 回调不验签、敏感字段不加密 |
| 支付宝开放平台签名 | RSA2（SHA256WithRSA） | 支付宝 2015 年定下的标准 | RSA（SHA1）老算法、MD5 |
| 对接第三方开放接口 | HmacSHA256（双方共享密钥） | 双方持有同一密钥即可验 | 把密钥写死在代码里 |
| Webhook 回调验签（自建） | Ed25519（非对称）或 HmacSHA256 | 公钥可分发，私钥不出服务器 | 回调不验签、先处理业务后验签 |
| JWT 登录态签名 | 单服务 HS256（密钥 ≥256 位）；多服务互验 RS256 / EdDSA | 自签自发够用就别上非对称 | `alg: none`、短密钥、密钥进仓库 |
| 数据库敏感字段加密 | AES-256-GCM（应用层）+ 附加认证数据绑字段 | 拖库只见乱码，且防密文搬字段 | ECB 模式、密钥与库同库存放 |
| 文件完整性校验 | SHA-256 | 快、够用、标准化 | MD5、SHA1（已可构造碰撞） |
| Git 提交签名 | SSH（Ed25519）或 GPG | 证明「这笔提交是我发的」 | 无 |
| 传输 | TLS 1.3 | 全站强制 | TLS 1.0/1.1、自签名证书上生产 |

## 二、强制红线

1. **不自己实现算法**——全部用成熟库（Java Bouncy Castle / Spring Security，Python `cryptography` + `passlib`，Go `golang.org/x/crypto`，Node `node:crypto` + `bcrypt`）。
2. **密钥永不入库、不进仓库**——走环境变量或密钥管理服务，`.env` 必须 gitignore；启动时校验密钥长度，不达标直接失败退出。
3. **密码只存哈希，永不存可逆密文**——服务器自己都还原不出来才是正解。
4. **哈希定长到的是「文件/报文没被改」，密码要的是「慢」**——两类哈希别混用。
5. **回调先验签、后处理业务**——验签通过前不落库、不发货、不调下游。
6. **签名比较用常量时间函数**——`hmac.compare_digest` / `crypto.timingSafeEqual`，不要用 `==`。
7. **日志必须脱敏**——密码、密钥、完整身份证/银行卡号一律 mask。

## 三、密码存储细则

**bcrypt cost 选型**：cost 每加 1 计算量翻倍（2^n 轮）。`10` = 1x（低频登录内部系统）；`12` = 4x（**默认推荐**，普通业务系统）；`13-14` = 8x-16x（高价值账号、C 端高峰）。目标单次哈希耗时 **100~300ms**。定完不频繁改——改了等于存量密码失效，需在用户下次登录时用新 cost 重算并覆盖（校验成功即重算升级）。

**Argon2id**（2015 年 Password Hashing Competition 冠军，NIST SP 800-63B 推荐）：`time_cost=3`（迭代轮数）、`memory_cost=65536`（64MB）、`parallelism=1~4`。与 bcrypt 的本质差别：bcrypt 靠「慢」防爆破，Argon2id 还靠「吃内存」防 GPU 并行爆破。

禁用清单：明文存储、可逆加密、MD5/SHA1/SHA256 裸哈希、无盐固定哈希、自研「轻量加密」。校验走库的哈希串（自带盐），不是自己算一遍比固定值；登录失败提示不区分「用户不存在」与「密码错误」；有频率限制/锁定。

## 四、支付回调处理顺序（错一步就出事）

1. **验签** → 失败直接拒绝，不落库不返回业务成功。
2. **解密敏感字段**（微信 APIv3：AEAD_AES_256_GCM，AAD 正确）。
3. **幂等处理**（同一 `transaction_id` 只处理一次）。
4. **返回应答**（微信要求 HTTP 200，失败也要返回 JSON 错误体，否则会一直重推）。

支付宝：签名 RSA2（SHA256WithRSA）；历史包袱——RSA（SHA1）与 MD5 老算法禁用；平台证书/支付宝公钥支持更新（多证书并存）。验签用常量时间比较。

## 五、JWT 与令牌选型

- 单服务自签自发：HS256（密钥 ≥256 位/32 字节，来自环境变量）
- 多服务互验：RS256 / EdDSA（私钥签发、公钥校验）
- 校验**固定期望算法，不读 header 的 alg**（防 `alg: none` 攻击）；校验 `exp / nbf / iss / aud`
- Access / Refresh 双令牌，Refresh 可撤销；登出后旧令牌立即失效（黑名单或短有效期）
- 密钥轮换：新旧密钥并存验证期过渡，不原地换钥

## 六、AI 写加密代码的约束块

让 AI 写这类代码时，把以下约束整段贴进 prompt（源 `references/ai-guardrails.md`）：

1. 禁止出现 MD5/SHA1 用于密码或签名；禁止 ECB；禁止硬编码密钥/盐/IV。
2. 随机值必须来自安全随机源（`crypto.randomBytes` / `secrets` / `SecureRandom`），禁止 `Math.random`。
3. IV 每次加密随机生成并与密文一起存储；禁止复用 IV。
4. 常量时间比较做签名校验；错误信息不区分具体原因（防枚举）。
5. 依赖写进依赖清单，禁止手写算法实现。

## 七、上线前自查清单（按场景勾选，不适用跳过）

**通用**：无硬编码密钥（搜 `secret`/`password`/`key` 字面量）；`.env` 在 gitignore、`.env.example` 只有键名；启动校验密钥长度不达标即退出；依赖进清单无手写实现；日志脱敏（CI 日志无完整密钥/密码/证件/银行卡）；随机值来自安全随机源。

**用户密码**：bcrypt(cost 12) 或 Argon2id；校验走库的哈希串；有重哈希升级路径；失败提示不区分用户不存在/密码错误；有频率限制/锁定。

**支付与回调**：验签在第一行，失败不落库不发货；常量时间比较；按交易号幂等；平台证书可更新（多证书并存）；APIv3 敏感字段解密 AAD 正确。

**JWT**：固定期望算法不读 header alg；密钥 ≥32 字节且来自环境变量；校验 exp/nbf/iss/aud；双令牌且 Refresh 可撤销；登出后旧令牌立即失效。

**数据落库**：敏感字段 AES-256-GCM 密文且带 AAD 绑字段；库里搜不到明文；密钥与数据不在同一存储。

**传输**：全站 HTTPS 无降级；只留 TLS 1.2/1.3；证书自动续期；内部敏感服务 mTLS 或服务间签名。

**供应链**：仓库接密钥扫描（gitleaks/trufflehog）且历史提交也扫过；依赖有锁文件；密钥泄露后已轮换而非只删除。

## 八、不做

- 不替用户决定业务需求（「这个字段要不要脱敏」是业务问题）。
- 不提供自研算法、魔改算法、「轻量加密」实现。
- 不锁定第三方库版本（由使用者按项目 `versions.md` 现场查询）。

源仓库有配套代码范式 `references/code-snippets.md`（四语言：密码哈希/字段加密/签名/验签/摘要），路径即此处，用途：AI 生成代码时的语言范式参照。
